# Known limitations

- `app/fixtures/shaft_bearing_v1.json` is illustrative hackathon content, not a validated mechanical procedure. Do not infer torque, tolerances, tactile claims or safe operating specifications from it.
- Gemini video extraction, private media upload/streaming, durable `MediaAsset`/`ProcessingJob` tables and a separate worker are implemented. Live extraction with `gemini-3.5-flash-lite` succeeded on a synthetic narrated clip and one Navy training film excerpt (see `V2_CHECKPOINTS.md`). Broader recording coverage and visual-only action quality remain unverified; quality is promising, not validated. The worker extraction call sets no `max_output_tokens`.
- Run a single worker for this hackathon deployment. Durable leases recover interrupted jobs; this is not a validated multi-worker deployment.
- Uploads accept only MP4 containers with h264/av1 video; QuickTime is rejected. Inspection checks ffprobe metadata, not a full video decode. `ffprobe` must be installed; generated-video tests also need `ffmpeg` and skip without either tool.
- Gemini timestamps are approximate and are not checked against video frames. Invalid intervals retain draft units without evidence and produce warnings; publication requires supported expert corrections or rejection of unsupported units. AI output is always unreviewed.
- Signed playback tokens can be reused for 10 minutes so seeking can make repeated range requests. They are scoped to one media ID, not single-use. Keep query tokens out of logs (`uvicorn --no-access-log`).
- Chunked uploads without `Content-Length` are size-bounded only after multipart spooling. Declared lengths have an earlier middleware bound; temporary disk capacity remains an operational concern.
- Processing requires a new task without a draft. A task with an existing draft returns `DRAFT_ALREADY_EXISTS` and cannot be reprocessed; create a new task. `mode=demo` cannot analyze uploaded recordings; use the seeded V1 fixture flow instead.
- Provider file deletion after success is best-effort; deletion errors do not fail completed jobs. Failed jobs retain provider file references and local media. No automatic media cleanup or raw extraction debug logging is implemented.
- Multilingual support, embeddings, advanced retrieval and AI viva scoring remain reserved; their flags and `LOG_MODEL_INPUTS` must stay false.
- Demo HMAC tokens are not production identity. Without a non-empty `DEMO_SIGNING_SECRET`, the signing key lives only in process memory and restart invalidates tokens. Multiple processes need the same explicit secret. Production demo flags must all be false; production identity remains outside V1.
- Without `ENABLE_LIVE_QA`/`ENABLE_LIVE_GAP_GENERATION`, Q&A and gap detection stay deterministic even with `AI_PROVIDER=gemini`. Deterministic Q&A is English-only weighted keyword ranking over approved snapshots; it is not semantic retrieval and may answer an off-target question from the wrong unit.
- Live Q&A only returns whole approved fields verbatim (exact-match support check). This proves conformity to approved assertions, not industrial truth or relevance to the question; relevance judgement is Gemini's and is not expert-validated. Live retrieval is the same keyword ranking (top three units); a relevant unit missed by ranking is never seen by the model.
- Live gap questions are model-generated and unvalidated for expert usefulness. Reference validation rejects invented unit/evidence IDs but cannot prove a question is non-leading or relevant. Concurrent distinct generation requests may both incur provider cost; the second returns `GENERATION_STALE`.
- AI evaluation datasets (`evals/`) are synthetic and illustrative. No expert-reviewed corpus exists; expert acceptance metrics are reported as unmeasured.
- SQLite supports a single writer. Every transaction starts with `BEGIN IMMEDIATE`, so requests are serialized (waiting up to the 5 s busy timeout); this keeps concurrent draft edits at 409 `REVISION_CONFLICT` and concurrent publishes idempotent, at the cost of read concurrency. Schema v1–v7 upgrades add tables and advance to v8; unsupported schema versions fail startup rather than dropping data. A schema-7 binary rejects a schema-8 database: roll back features by disabling flags, or restore the pre-upgrade backup with the older binary. Back up databases before upgrades.
- No `validate_required_knowledge` endpoint exists. Simulation clients check required IDs against `training-pack.knowledge_units[].id`.
- The integrated `/learning` routes handle current course progression, simulation replay, structured viva and learner reset. The older demo reset `scope: "attempts"` still returns `RESET_SCOPE_UNAVAILABLE`; use `/learning/reset`. A full fixture reset now clears learner tables and AI diagnosis runs as well.
- Exported API examples contain real run IDs and timestamps, so regeneration changes those values. Auth tokens are redacted. Some of the 16 acceptance steps assert the preceding response rather than sending a new request; their example files repeat that request/response.
- Current FastAPI/Starlette emits a TestClient deprecation warning for httpx. Tests still pass; dependency modernization is outside this checkpoint.
- Gemini video extraction returns `MM:SS` strings that code converts to milliseconds; one full-clip run was correct, so timestamp accuracy is promising, not validated. Transcript providers (Ollama, OpenRouter) still accept integer coercion from strings (for example, `"100"` → `100`).
- The `admin` role may upload media.
- Experts may publish from Studio; publication is not reviewer-only.
- A missing Gemini key fails at request time rather than startup.
- Any expert can access any task; there is no per-expert task ownership.
- Token usage is stored in `processing_jobs.usage` but is not exposed by `GET /jobs/{id}`.

## Integrated Studio diagnosis demo

- Source-note diagnosis uses three bounded Gemini calls for extraction, patch proposal and source-consistency critique. `GEMINI_API_KEY` automatically enables live diagnosis independently of the legacy video worker flags. Live course-video diagnosis with `gemini-3.5-flash-lite` was verified on a synthetic narrated clip (thinking `low`) and on a 230 s narrated U.S. Navy bearing training film excerpt (thinking `medium`: 13 observations, 3 proposals, critique passed).
- Exact-quote checks are substring checks. When an uncertainty qualifier (`usually`, `may`, `likely`, …) or negation (`not`, `n't`, `never`, `without`, …) precedes a quote in the same sentence, the quote is extended to the sentence start, so "usually means X" and "does not usually mean X" cannot become "X". Sentence boundaries are `.`, `!` or `?` followed by whitespace, or a newline: decimals do not end sentences, but abbreviation periods such as `approx. ` still do. A quote whose occurrences extend differently is dropped as ambiguous. Other meaning changes from sub-quoting are not detected, and the AI critique is not a reliable guard. Expert review remains required.
- Video observations vary between runs and are the only source the proposing agents see; the video is attached to the observation call only, so proposals cannot quote narration the observer missed. With thinking `low`, Flash-Lite observed only the first 5–38 s of the 230 s film and the run either failed (`AI_OUTPUT_UNSUPPORTED`) or produced no units. With `medium`, the stored Studio run covered 0–230 s in 13 in-range segments; a separate direct `medium` call skipped 69–110 s and returned intervals past the video end, which the service rejects as `AI_OUTPUT_INVALID`. In 3 measured `medium` runs on the 230 s film, one observer paraphrased narration (for example, "Recording identification numbers and taking measurements…") while labelling it spoken. Proposals quoting such paraphrases pass the substring check and the AI critique; verbatim narration is not verified. Observers may split one sentence across segments, producing fragment proposals. Studio's first pass now supports up to twelve units, with source-anchored learning gaps and expert questions. The expanded prompt has not yet been verified in a new live run.
- Without a key, live diagnosis is unavailable. An illustrative authored rehearsal must be explicitly selected; there is no automatic fixture fallback. Custom source notes require a key; a failed live run never silently replays fixtures. Only exact quoted source extracts become proposals, and human approval is always required to apply/publish.
- Demo mode removes the separate admin grant. All public publication paths still require a current passing evaluation. Structural/source checks are not a mechanical safety certification.
- The Studio UI accepts uploaded course video, scripts and optional expert review notes. The apprentice course uses the latest uploaded video when media streaming is enabled. Live spoken interviewing remains deferred; the viva uses deterministic reviewed-content templates, and reflections are ungraded.
- The connected course remains the bearing task `task_001`. Its simulation scenarios and mechanics remain authored. Course content and newly prepared interview scripts consume the active approved release.
- Release changes start a fresh learner context. Complete historical learner enrollment/report retention, production identity, revocation and enterprise review queues remain future work.
